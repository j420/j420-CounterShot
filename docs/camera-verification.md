# Five camera iterations — observed verification

Actual Meta checks observed on 2 November 2026; integrated software review rechecked on 3 November 2026. The application implements five camera-guidance profiles and a shared before/action/after/review loop. **No successful physical trial or comparative advantage has been demonstrated.** The real API checks used clearly labelled rendered diagrams; native phone capture still needs verification on the deployed HTTPS application.

## What was built

The camera workbench has a real rear-camera preview, explicit frame inspection, an uploaded-still fallback, snapshot-bound visual regions, one proposed action with its expected visible result and stop condition, optional read-aloud, and an explicit three-check watch budget. Camera tracks stop on cancellation, navigation or page hiding. Watching never confirms a step automatically.

Each profile has four distinct phases with confirmed scope/resources, named observations, reversible recovery, before/after frame binding and explicit operator checks. Thirteen phase-specific numeric comparisons cover measured bend/slack, fragment gaps and actual outline width/height within a declared tolerance, tail reserve, gasket height and water collection. A failed reading overrides checked boxes; failed/incomplete reviews retain the actual values and original facts without advancing.

The [iteration record](camera-iterations.md) describes the physical problem, falsification case, first real test and ordinary-aid baseline for each profile. The [independent credibility review](camera-credibility-review.md) separates these implemented controls from unearned physical/novelty claims.

## Review findings corrected

The [3 November independent review](four-eyes-review-2026-11-03.md) records the additional reproduced issues and regressions: target grounding, fragment outline measurements, versioned historical checks, interrupted upgrades, browser response/freshness races, immutable comparison context, pre-request cancellation, operator-review context, animation/decode limits and exact displayed evidence. Camera engine 1.2.0 and prompt 1.0.2 have offline coverage; there was no new live Meta evaluation during this review.

- Numeric limits previously relied on checkbox/narrative review. Raw operator readings now control the bound, including the independently reproduced 1 mL result against a 10 mL minimum.
- Missing operator-resource facts could initially leave the first gasket action enabled. All 20 phases now require scope and resource facts.
- A pending/failed newer view could leave old ready guidance available. New checks withdraw that guidance; failure/expiry cannot revive it, and pending confirmation is blocked.
- Clearing a completed phase's active views could leave the next phase without a comparison image. The server now resolves the last completed owned after-view in the same scene epoch; an API regression uses the actual adapter with two image inputs.
- Client clock skew could extend the display of stale advice. The UI now anchors age to server time plus monotonic elapsed time and requires a refresh after returning from a hidden page.
- A numerically failed review requested as incomplete could display the wrong notice. The notice uses the derived saved outcome.
- Phone guidance was too far below the preview. The mobile layout now places a current-frame cue beside the view and keeps capture controls reachable. Boxes remain on the saved frame.

Frame size/type/decode, ownership, duplicate operations, stale revisions, expired inference, late traces, scene changes, malformed regions and request budgets also have regression coverage. These controls do not establish the feasibility of an arbitrary free-text physical action.

## Evidence still required

Each profile needs its actual compatible objects, measured facts, camera-guided physical attempt, all interventions, complete operation/release/reset and a consequential tested correction. Compare with an equally informed direct assistant and a sensible diagram/checklist/support baseline, with equivalent supplies and setup costs. A held-out change must alter a relationship inside a physically demonstrated scope.

Camera actions do not inherit the jig companion's symbolic hand/support/geometry proof. No one-hand method, force rating, precise AR registration, leak integrity, electrical continuity or manufacturing accuracy is earned by these software results. Uniqueness/market novelty and participant Official Rules are separate questions.

The public Vercel/backend deployment and a real iPhone/Safari plus Android/Chrome trial remain outstanding.
