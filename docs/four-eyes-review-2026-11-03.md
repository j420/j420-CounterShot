# Independent review — 3 November 2026

Six independent review passes covered the camera domain/state engine, camera API/persistence, Meta adapter, browser interaction, native media/runtime boundaries, and the earlier jig/job/construction paths. Follow-up cross-reviews examined the integrated version and timing changes. Confirmed defects were reproduced, corrected and given regression coverage. No new Meta requests, external deployment or environment publication occurred during this review.

## Corrected findings

All findings below were P2 correctness or reliability defects in this prototype. No confirmed P0/P1 finding remains from this review. Severity does not certify physical operation.

| Finding | Reproduction and consequence | Correction and regression evidence |
| --- | --- | --- |
| Camera actions could lack a located target | `inspect`/`measure` bypassed the physical-target gate; an observation with a null box could also admit a move. | Every admitted `perform`, `inspect` or `measure` action requires valid referenced observations with boxes. Domain tests exercise each kind and missing/null targets. |
| Negative reviews could bind to the wrong phase | A scene change reset the phase/epoch while retaining an older latest turn. A failed/incomplete review could then attach to the new phase. | Reviews require an active session and a turn matching the current phase. Scene-change and wrong-phase regressions reject the write. |
| Fragment completion lacked an actual outline comparison | A checked “outline compared” box permitted a reconstruction about 200 mm wider than the stated reference. | Both outline phases require operator-entered width and height within a separately confirmed tolerance. Out-of-bound values fail despite checked boxes. Domain and browser tests retain the original criterion after facts change. |
| Old rules could appear current after an upgrade | A completed old fragment run could remain complete under newly added outline checks, and old reviews were displayed using the current catalog. | Sessions retain the original workflow definition and schema/engine/hash. Changed or unrecorded rules are held until an explicit facts reset. New reviews retain immutable step/facts/version snapshots; old unversioned reviews are labelled historical without invented criteria. |
| A pending old run could prevent the required upgrade reset | An interrupted pending turn in an old-version session remained locked forever because historical reads correctly avoided mutating it. A reset could also retain the old active pointer. | Historical pending work no longer locks facts review or triggers indefinite polling. | Comparison pixels and context were not one immutable reference | Retried after-views could lose the original expected result; previous image bytes were not checked against their stored hash before inference. | One owned saved turn supplies its frame, assessment and instruction. ## Version and evidence boundaries

- Camera engine: **1.2.0**. New sessions/turns bind their workflow/check versions; original reviews are not backfilled with new criteria.
- Camera prompt: **camera-closed-loop-1.0.2**. Its request context changes were verified offline. The seven earlier actual Meta camera requests used the archived earlier configuration; their response IDs, failures, bytes/hashes, timing and 31,038-token total were not rewritten or attributed to this prompt.
- Aggregate construction compiler: **3.0.2**; legacy compiler: **2.0.1**. The workshop-specific compiler remains **3.0.1** because its construction serializer did not change. Archived workshop SVGs/provider fixtures retain their original versions. Queued jobs still require their frozen execution versions.

## Verification

The final integrated run passed **271 automated tests**, with zero failed or skipped, and **20 Chromium journeys** against the optimized production build. TypeScript, the Next.js build and the final Docker build passed. The container HTTP smoke verified all five current-version profiles, private ownership, response timing, no-key HTTP 503 and persistence across restart. Detailed results are recorded in [verification.md](verification.md) and [camera-verification.md](camera-verification.md). All review tests use mocks or synthetic local inputs. Browser checks use isolated storage and a backend without a provider key or worker. Historical fixture replay is not a new model evaluation.

## Remaining material limits

The five profiles are implemented software exploration workflows. No real physical trial, comparative benefit, independent novelty finding, guaranteed realtime interaction or physical safety/force qualification was established by this review. The earlier synthetic Meta checks all withheld physical admission, including the paired-image check. The revised prompt has not had a new live evaluation.

The Vercel plus persistent-backend public deployment and real iPhone/Safari and Android/Chrome camera checks remain outstanding. Those are the next practical validation steps before a hackathon demonstration claims reliable phone use. The original [jig review](four-eyes-review.md) and [credibility review](camera-credibility-review.md) retain their separate physical-evidence boundaries.
