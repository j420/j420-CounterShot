# Four-eyes review — 2 November 2026

The review found and corrected significant isolation, worker-concurrency, evidence-validation and construction-output defects. The reviewed software passes the checks below. A compatible physical workpiece, an admitted jig and demonstrated operator benefit are still outstanding. A successful production build is not evidence of production operation or successful assembly.

## Scope and method

Independent reviewers examined domain/state-machine and geometry code; Meta integration and job recovery; HTTP/session/storage and evidence integrity; UI workflows; and product/hackathon claims. The integrating reviewer reproduced failures, reviewed the patches and ran the combined checks. A second pass examined mutation receipts, trace-export privacy and interactions between worker fencing and recovery. Reviews used adversarial inputs, controlled concurrent attempts, offline provider stubs and an isolated production web server.

This review made no live Meta requests, deployed nothing and did not change or publish the cloud environment configuration. Browser and media exercises used synthetic records in temporary storage. Previously recorded real Meta responses remain historical API evidence; they were not rewritten or relabelled as new runs.

## Remaining limits and required evidence

1. **Physical admission is the main blocker.** No selected/measured real six-panel kit has yet demonstrated the assumed assembly topology. Exterior braces may permit inward tipping or lose location under insertion force. Test hand release and the actual next action at every support transfer, then joints, gate parking, extraction, alignment and reset. See the [build brief](workshop-build-brief.md).
2. **Video validity does not establish trial truth.** Decode checks establish usable visual media, not an uninterrupted complete operation, unique attempt or honest review. A person must inspect the exact clip and build. Reuse/reupload of the same footage as another trial is not automatically detected; do not treat stored trial counts as independently verified repetitions.
3. **A full page reload loses the UI's pending retry identity.** Server receipts remain durable, but the current page keeps its request-ID map in memory. After an uncertain save and reload, inspect saved records before creating another attempt. In-page retries and the dedicated refresh action are covered.
4. **Production operation is unproven.** The Docker image has not been independently built here; deployment, backup restoration, multi-host operation, account/session recovery and automated local/provider-media deletion remain outside the completed checks. The documented persistent single-host prototype and access code are the current deployment scope.
5. **Comparative and adaptation claims need real results.** Record complete operator trials and a consequential physical revision. Compare with sensible ordinary aids and an equally informed direct assistant using equivalent supplies; freeze a held-out case and budget. Local checker repairs show software integration, not superior real-world performance.
6. **Full participant rules remain unverified.** The supplied event text describes Indie judging as creativity, technical ambition and whether it works; Startup judging emphasizes technical execution and production operation. Equal weights apply to application selection, not a published final-judging rubric. The text supplies neither final judging weights nor a requirement to use every model. Verify the participant Official Rules and submission portal before claiming eligibility or compliance.

The review supports continuing toward a real admission trial with a more reliable software prototype. It does not support a claim that the jig is physically proven, that it outperforms ordinary aids, or that the submission is production-ready.
